# i18n Migration Documentation

## Overview

This project has been migrated from a custom translation context to use the industry-standard `next-i18next` library for internationalization (i18n).

## Changes Made

### 1. Package Updates
- **React**: 18.3.1 → 19.2.0
- **React-DOM**: 18.3.1 → 19.2.0
- **Next.js**: 14.0.0 → 15.4.7
- **New Dependencies**:
  - `i18next@23.15.2`
  - `next-i18next@15.2.0`
  - `react-i18next@14.1.3`

### 2. Configuration

#### `next-i18next.config.js`
```javascript
module.exports = {
  i18n: {
    defaultLocale: 'vi',
    locales: ['en', 'vi', 'pl'],
    localeDetection: false,
  },
  // ...
};
```

#### `next.config.js`
Created with i18n configuration from `next-i18next.config.js`.

### 3. Translation Files

Translation files are now stored in `public/locales/{locale}/common.json`:

- `public/locales/vi/common.json` - Vietnamese (default)
- `public/locales/en/common.json` - English
- `public/locales/pl/common.json` - Polish

**Note**: English and Polish translations currently use the English keys as values. You should update these with proper translations.

### 4. Code Changes

#### Before (Custom Context)
```tsx
import { useTranslation } from '~/contexts/translation-context';

const MyComponent = () => {
  const { t } = useTranslation();
  return <div>{t('Hello')}</div>;
};
```

#### After (next-i18next)
```tsx
import { useTranslation } from 'next-i18next';

const MyComponent = () => {
  const { t } = useTranslation('common');
  return <div>{t('Hello')}</div>;
};
```

#### For Pages with SSR
```tsx
import { serverSideTranslations } from 'next-i18next/serverSideTranslations';

export async function getServerSideProps(context) {
  return {
    props: {
      ...(await serverSideTranslations(context.locale || 'vi', ['common'])),
      // ... other props
    },
  };
}
```

## Usage Guide

### Adding New Translations

1. Add the translation key-value pair to all locale files:

```json
// public/locales/vi/common.json
{
  "common": {
    "new_key": "Giá trị tiếng Việt"
  }
}
```

```json
// public/locales/en/common.json
{
  "common": {
    "new_key": "English value"
  }
}
```

2. Use in your component:
```tsx
const { t } = useTranslation('common');
<div>{t('new_key')}</div>
```

### Changing the Language

Currently, the language is set to Vietnamese by default and locale detection is disabled. To change this:

1. Update `next-i18next.config.js`:
```javascript
module.exports = {
  i18n: {
    defaultLocale: 'en', // Change default locale
    locales: ['en', 'vi', 'pl'],
    localeDetection: true, // Enable automatic detection
  },
  // ...
};
```

### Adding a Language Switcher

To allow users to switch languages, you can create a component like this:

```tsx
import { useRouter } from 'next/router';

const LanguageSwitcher = () => {
  const router = useRouter();
  const { locale, locales, pathname, query, asPath } = router;

  const changeLanguage = (newLocale: string) => {
    router.push({ pathname, query }, asPath, { locale: newLocale });
  };

  return (
    <select value={locale} onChange={(e) => changeLanguage(e.target.value)}>
      {locales?.map((loc) => (
        <option key={loc} value={loc}>
          {loc.toUpperCase()}
        </option>
      ))}
    </select>
  );
};
```

### Creating Additional Namespaces

If you want to organize translations by feature:

1. Create new files:
   - `public/locales/vi/auth.json`
   - `public/locales/en/auth.json`

2. Use in components:
```tsx
const { t } = useTranslation('auth');
```

3. Add to serverSideTranslations:
```tsx
...(await serverSideTranslations(context.locale || 'vi', ['common', 'auth']))
```

## Troubleshooting

### Translation not showing up
- Ensure the key exists in the translation file
- Check that you're using the correct namespace (e.g., 'common')
- Verify the translation file is valid JSON

### Build errors related to @gen files
- These are pre-existing issues not related to the i18n migration
- The missing @gen files need to be generated by the project's code generation tools

### Page not loading translations
- Ensure `serverSideTranslations` is included in `getServerSideProps`
- Check that the page is wrapped with `appWithTranslation` in `_app.tsx`
